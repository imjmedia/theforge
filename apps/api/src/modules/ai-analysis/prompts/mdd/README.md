# Prompts MDD

- **`mdd-constitution-skeleton.md`** — Forma objetivo del documento: siete secciones, trazabilidad §1→§3→§4, §4.A (API propia) antes de §4.B (externas), profundidad mínima en §5, YAGNI. Encabezados en español aunque el brief venga en inglés. §3 muestra fences `sql` y `TechnicalMetadata` **a nivel de párrafo** (no dentro de viñetas); el pipeline `promoteListItemFences` normaliza salidas legacy del LLM. Referenciado en Clarifier y Software Architect; exportado en `load-prompts.ts` como `MDD_CONSTITUTION_SKELETON_MARKDOWN`. Además, `normalizeMddEnglishSubheadings` en `utils/mdd-sanitize.ts` corrige subtítulos EN frecuentes al volcar el borrador.
- **`mdd-governance-patterns-wizard.md`** — Sección inmutable **SSOT** de patrones de desarrollo (wizard con `[ ]` / `[X]`). Fuente compartida con `@theforge/shared-types/mdd-governance-patterns`. Se inserta bajo el `#` del MDD vía `ensureMddGovernanceSection` en `prepareMddForOutput`; edición parcial con `updateMddGovernancePatterns` (solo wizard, conserva §1–§7). Los entregables reciben patrones activos en el user prompt (`appendMddGovernancePatternsToPrompt`). UI: `MddPatternsWizardDialog` (`initial` / `edit`). **Incompatibilidades** (p. ej. microservicios ↔ monolito modular): `@theforge/shared-types/mdd-governance-pattern-compat` corrige la selección; el Workshop pide confirmación antes de generar; `runMddGenerationJob` aplica la misma corrección como red de seguridad en jobs en background.
- Otros `.md` — clarifier, arquitecto (§2–§4 monolítico LOW/MEDIUM; scopes §2/§3/§4 vía prefijos en `mdd-architect-pipeline.util.ts`; **no** infiere `messages`/`conversation_memory` por chat de taller — solo dominio BRD), seguridad, integración, auditor, manager, etc.
