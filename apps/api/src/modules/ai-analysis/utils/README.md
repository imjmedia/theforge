# Utils (ai-analysis)

Utilidades compartidas entre nodos MDD y Benchmark para evitar código duplicado.

- **mdd-tail-parallel.config.ts** – Flag `MDD_TAIL_PARALLEL` (activo por defecto; `0` restaura `security_integration` solo §6∥§7).
- **mdd-tail-parallel.util.ts** – Merge determinista §5+§6+§7 (`mergeTailParallelResults`), placeholder §5 post-SA, detección primera pasada para `section5`. Tests: `mdd-tail-parallel.util.spec.ts`.
- **parse-json.ts** – `parseJsonOrThrow(text, schema)`: parsea texto que puede contener JSON con o sin markdown code fence; usado por nodos MDD (manager, clarifier, security, integration, auditor). El agente Benchmark (scout, etc.) puede migrar a este util en el futuro para homologar.
- **mdd-sanitize.ts** – `normalizeMddFormat(draft)`: estandariza títulos (## 2. Modelo de datos, ## 3. Contratos de API), elimina líneas huérfanas con solo un número, envuelve SQL en ```sql si viene en texto plano, formatea JSON en Contratos de API (```json + pretty-print), e inserta `---` antes de cada `##` para separación visual (`ensureHorizontalRuleBeforeH2`). Corrige sección 2: SQL no cerrado antes de ### Diagrama / ```mermaid y encabezado pegado "### Diagrama entidad-relaciónmermaid" (`fixSection2UnclosedSqlAndGluedMermaid`). En Seguridad/Integración convierte JSON con `"heading"` o `"section"` + `"details"` a markdown (`sanitizeSeguridadIntegracionRawJson`, `convertSectionDetailsJsonToMarkdown`). Además descontamina el formato "bullet list as JSON lines" (cuando cada línea es una viñeta con un fragmento de JSON: `- {`, `- "title": ...`, `- "content": [`), reconstruyendo el JSON y convirtiéndolo a markdown legible (`unbulletAndParseSectionJson`, `objectWithContentArrayToMarkdown`). `jsonSectionToMarkdown`, `sanitizeContextSection`, `replaceContextWhenOnlyMetadata`, `preserveContextSectionIfSubstantial`, `ensureContratosSection`. **`sanitizeMddAtPersist`** (coherencia determinista): despega encabezados pegados, fences, JSON §4, HR rotas, UI/UX MVP; termina con **`finalizeMddPersistFormatting`** (`repairGluedMarkdownHeadings` + `collapseInlineHorizontalRules`) para evitar regresiones post-pasada. **`prepareMddMarkdownForPersist`** (SSOT al guardar): `formatDocumentMarkdown` → `sanitizeMddAtPersist` → `formatDocumentMarkdown` (segunda pasada estructural tras coherencia de negocio; evita que `repairAsciiDiagramBlocks` re-envuelva SQL/ER o que sanitize reintroduzca fences rotos en §3/§4). Invocado al final de **`prepareMddForOutput`** y directamente en `projects.update` con `mddFormatOnly` / `legacy-coordinator.generateMdd`. Tests: `mdd-sanitize.spec.ts`.
- **mdd-prepare-output.ts** – Pipeline semántico del MDD (prefer draft vs structured, diagramas, UI/UX, gate fixes, merge dominio BRD/DBGA) y cierre con **`prepareMddMarkdownForPersist`** para que generación, persist parcial y pipeline compartan el mismo markdown formateado. Tests: `mdd-prepare-output.spec.ts`.
- **suggest-mdd-governance-patterns.util.ts** – Preselección SSOT con **LLM** (temp 0, `governancePatterns` 2K tokens). Prompt compacto: catálogo acotado (~18–28 ids), contexto arquitectónico extraído (~7.5K chars) y ranking determinista como pistas. Sin docs → respuesta vacía sin LLM. **`suggest-mdd-governance-patterns-context.util.ts`** extrae secciones/stack. Tests: `suggest-mdd-governance-patterns.util.spec.ts`.
- **mdd-domain-prompt.util.ts** – Inventario de dominio desde `brdContent`/preámbulo BRD para Clarifier/SA/Critic/Auditor; detecta auth-skew (`mddStateHasDomainAuthSkew`).
- **mdd-diagram-suggestions.ts** – `suggestMddDiagrams(draft)`: analiza el MDD y devuelve sugerencias de diagramas Mermaid a insertar (erDiagram en modelo de datos si hay CREATE TABLE; stateDiagram-v2 en contratos si hay auth/login; flowchart en frontend si hay componentes). **`sqlToErDiagramContent(sql)`** deriva el erDiagram de forma determinista desde `CREATE TABLE`/`REFERENCES` (SSOT; pisa salida del LLM). `injectMddDiagrams(draft, suggestions)` inserta o **reemplaza** el bloque ER existente. `regenerateErDiagramFromSql(draft)`: regenera solo el erDiagram de la sección 3 desde el SQL. Usado por el nodo `mdd-diagram-injector`, `prepareMddForOutput`, `parseModeloDatosFromSection3Markdown` y por el comando del Manager "regenerar diagrama ER".
- **mdd-pre-render.ts** – Re-export desde `engine/mdd-pre-render.ts`. `preRenderMddSanity(draft)`: valida Mermaid (sin coma PK/FK, espacios normalizados) y tablas markdown en §4 (alineación segunda fila, sin líneas en blanco). Devuelve `{ ok, code?, message? }`; códigos `ERR_MERMAID_SYNTAX`, `ERR_TABLE_SYNTAX`. Usado en `projects.service` antes de persistir `mddContent`.
- **mdd-delivery-gate.util.ts** – `validateMddForDelivery`: gate bloqueante MDD. Con BRD/DBGA ejecuta **`prepareMddForDeliveryGateValidation`** (BRD patch, inventario §3/§4, SSOT, fences/manifest) antes de evaluar. **Blockers humanos:** solo `brd-decision-log:*`. Trazabilidad BRD→MDD, dominio e issues auto-reparables → **warnings** (el semáforo sigue midiendo trazabilidad por score). `isHumanRequiredDeliveryGateBlocker` documenta la regla.
- **mdd-complexity-rigor.ts** – Apéndices de prompt según `mddComplexity` (LOW/MEDIUM/HIGH): `clarifierComplexityAppendix`, `softwareArchitectComplexityAppendix`, `auditorConstitutionRigorAppendix`, `contextSynthesizerComplexityAppendix` (regenerar §1). Alineado con la relajación de gaps en `EstimationService` para el mismo nivel.
- **mdd-inject-ui-mcp-frontend.util.ts** – Si hay MCP gráfico compatible activo, inyecta su librería en **§2 Frontend → Stack UI → UI Library** (`injectUiMcpIntoMddFrontendSection`, append ` + {label}` idempotente). `formatUiMcpLibraryLabel` deriva el texto desde `getActiveCompatibleMeta`. `buildUiMcpFrontendArchitectHint` alimenta el prompt del Arquitecto. Integrado en `prepareMddForOutput`, `mdd-prepare-output.node` y `createMddGraph*`. Tests: `mdd-inject-ui-mcp-frontend.util.spec.ts`.
- **mdd-clarifier-draft.util.ts** – `finalizeClarifierDraft`: evita que el Clarifier sobrescriba borradores sustanciales con §1 mínima cuando el DBGA es grande; hidrata §1 desde scope/DBGA. Usado en `mdd-clarifier.node.ts`. Tests: `mdd-clarifier-draft.util.spec.ts`.
- **mdd-delivery-gate-loop.util.ts** – Auto-loop del gate (`resolveDeliveryGateFixTarget`, `needsFullArchitectPipelineRegeneration` para draft cascarón §1–§2 + §3–§7 faltantes → `software_architect`). Tests: `mdd-delivery-gate-loop.util.spec.ts`.
